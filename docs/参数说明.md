# 参数说明（规则文件 / CLI / API / Web 四端对照）

> 本文档整合 ObjectAnalyzer 全部分析参数：哪些通过**规则文件**配置（分析"标准"，可入库可复用），哪些通过 **CLI / API / Web** 传入（本次运行的执行选项）。标注 [全] 表示四个入口均可用，[C]/[A]/[W] 表示仅特定入口可用。
>
> - 规则文件全量模板见 `samples/rules_full_reference.jsonc`（逐项中文注释）
> - Mini API 端点文档见 `http://localhost:5200/scalar`
>
> ⚠ 状态说明：核心选项模型正在重构（`Analysis/Options/` 分组 + `RulesToOptionsConverter`），本文档反映撰写时点的 HEAD 状态；API 的异步分析/预检/取消接口由并行开发提供。

## 一、规则文件参数（.json / .jsonc，支持 // 注释）

规则文件分两层：**`fields` 字段规则**（分析"标准"）与 **`runtime` 运行时配置**（"怎么跑"），外加两个独立顶层键。

### 顶层键

| 键 | 作用 | 说明 |
|----|------|------|
| `fields` | 字段规则字典 | 键为字段路径（嵌套写 `a.b.c`），值为该字段的规则集，见下表 |
| `runtime` | 运行时配置节点 | 本次分析的执行参数，按功能分子对象，见下表 |
| `valueParsers` | 值解析器 | Excel 多列 JSON 专用：配置后强制按 excel-json 格式解析，**普通 JSON 勿配** |
| `expectations` | 数据集期望 | `minRowCount` 最少行数、`maxDuplicateRate` 重复率上限；触发质量门禁 |

### `runtime` 运行时配置（按功能分子对象）

| 子对象 | 作用 | 主要键 |
|--------|------|--------|
| （直属） | 解析行为 | `flatten` 展平嵌套、`csvInferNumbers` CSV 数字推断、`maxValuesToShow` 展示数量、`maxParallelism` 并行度、`allowUnknownRules` 未知规则键放行 |
| （直属） | 字段选择与过滤 | `selectedFields` 仅统计字段、`filter` 过滤表达式（等价 --where） |
| `sampling` | 采样 | `reservoir` 蓄水池、`step` 等距步长 |
| `jsonPath` | JSONPath 投影 | `root` 文件根、`record` 记录级 |
| `schema` | Schema 演进 | `snapshot` 快照导出、`diffBaseline` 基线、`diffReport` 报告、`allowBreakingChanges` 门禁（退出码 6） |
| `distribution` | 分布漂移 | `snapshot` / `diffBaseline` / `diffReport` / `lowConfidenceWidth` 置信宽度 |
| `pii` | PII / 合规 | `off` 全局关闭、`report` 合规报告路径、`failOnLevel` 门禁（退出码 4） |
| `gates` | 质量门禁 | `failOnViolations`（退出码 3）、`failOnOutlierRatio`（退出码 5） |
| `deepAnalysis` | 深度分析开关（P4，默认全关） | `correlation` 相关性、`stringPatterns` 模式归纳、`unicodeHygiene`、`timeSeries`、`distributionSnapshot`、`fuzzyDedupField` |
| `checkpoint` | 大文件容错 | `path` 检查点输出、`resumeFrom` 续跑、`baseline` 基线合并 |
| `memory` | 内存预算 | `maxMB` 上限、`mode` soft/hard |
| `progress` | 进度 | `enabled` 进度条/ETA 开关 |
| `audit` | 安全审计 | `log` NDJSON 路径、`operator` 操作者 |
| `outputs` | 输出路径 | `primary` 主报告、`violations` 违规清单、`quality` 质量报告、`schemaCode` Schema 代码 |

### `fields.字段名` 的字段规则

| 键 | 作用 | 示例 |
|----|------|------|
| `primaryType` | 期望主导类型 | `String` / `Number` / `Boolean` / `DateTime`，不符时报告提示 |
| `enumValues` | 合法值白名单 | `["Male","Female"]`——出现之外的值记违规 |
| `required` | 每条记录必须有该字段 | 缺失记违规 |
| `pattern` | 正则，字段值必须整体匹配 | `"^1[3-9]\\d{9}$"`（手机号） |
| `minValue` / `maxValue` | 数值下限/上限 | 超出记违规 |
| `defaultValue` | 记录缺失时补齐的值 | 覆盖自动推断 |
| `unique` | 值不允许重复 | 适合订单号、编号 |
| `nullRateMax` | 空值占比上限（0~1） | `0.2` = 最多 20% 为空 |
| `maxOutlierRatio` | IQR 离群点占比上限（0~1） | `0.05` = 最多 5% |
| `pii` | 标记为业务敏感字段 | `label` 名称、`highSeverity` 等级、`mask.keepPrefix/keepSuffix/maskChar/maskAll` 打码格式 |
| `redact` | `false` = 豁免自动 PII 打码 | 误报白名单 |
| `transform` | 值转换 | `type`: jwt / aes / base64 / url / sm4 / sm2；参数 `claim` / `key` / `iv` / `mode` / `padding` / `format` / `privateKey` / `publicKey`；密钥支持 `kms:` 引用；`parse:"json"` 展开内层字段 |

## 二、执行参数（CLI / API / Web 按入口对照）

### 数据源与输入

| 功能 | CLI | API | Web | 说明 |
|------|-----|-----|-----|------|
| 上传/指定数据文件 | `-i <文件>` | multipart `file` 字段 | 数据源上传区 | [全] 支持 JSON/JSONL/CSV/Excel/XML/YAML 与 gzip/bzip2/zip 压缩包 |
| 粘贴数据文本 | — | `POST /api/analyze/raw?format=` 请求体 | — | 适合前端直接把文本交给 API |
| 数据库直连 | `--connection` + `--query` + `--provider` | — | — | PostgreSQL/MySQL/SQLite/SQL Server，惰性流式读取 |
| 强类型反序列化 | （已移除 `--type`） | — | — | v1.1 起移除，改用规则文件/JSON Schema 校验数据 |

### 解析行为

| 功能 | CLI | API | Web | 说明 |
|------|-----|-----|-----|------|
| 展平嵌套字段 | `--no-flatten`（取反） | `flatten` | 展平嵌套开关 | 也可由规则文件 `flatten` 提供 |
| CSV 数字推断 | `--no-csv-number-inference`（取反） | — | CSV 数字推断开关 | CSV 列的 `"30"` 是否按数字统计 |
| 未知规则键放行 | `--allow-unknown-rules` | — | 未知键放行开关 | 规则文件里出现数据中不存在的字段时不报错 |
| 文件根 JSONPath | `--root-path` | `rootPath` | 文件根 JSONPath | 仅整体 JSON 生效，如 `$.data[*]` |
| 记录级 JSONPath | `--record-path` | `recordPath` | 记录级 JSONPath | 每条记录生效，如 `$.payload` |

### 字段选择与值处理

| 功能 | CLI | API | Web | 说明 |
|------|-----|-----|-----|------|
| 字段选择 | `--fields` | `fields` | 统计字段 | 优先级高于规则文件 `runtime.selectedFields` |
| 过滤表达式 | `--where` | `filter` | 过滤条件 | 优先级高于规则文件 `runtime.filter` |
| 值转换/字段过滤规则 | `-r 规则文件` | `rules` 文件或 `rulesJson` | 规则上传 + 粘贴 JSON | 见第一节 transform |

### 采样（超大文件）

| 功能 | CLI | API | Web | 说明 |
|------|-----|-----|-----|------|
| 蓄水池随机采样 | `--sample-reservoir` | `sampleReservoir` | 蓄水池采样 | 均匀抽取最多 N 条 |
| 等距系统采样 | `--sample-step` | `sampleStep` | 等距采样步长 | 每 N 条取 1 条 |

### 输出与展示

| 功能 | CLI | API | Web | 说明 |
|------|-----|-----|-----|------|
| 报告导出 | `-o`（六格式自动路由） | 结果即响应 JSON | 报告下载按钮（JSON/HTML/MD/CSV/Excel/PDF） | API 返回 camelCase 完整结果，前端自行渲染/下载 |
| 违规清单导出 | `--violations` | —（违规内嵌 result） | 违规下载按钮 | 枚举/范围/必填等违规明细 |
| 质量报告导出 | `--quality` | — | — | Pass/Fail 摘要 + 逐字段明细 |
| 每字段展示值数量 | `--max-values` | `maxValues` | 最大展示值 | ⚠ 仅影响控制台报告，不改变结果 JSON |
| Schema 代码导出 | `-s`（7 种目标） | — | Schema 下载按钮组 | C#/TS/JSON Schema/OpenAPI/Proto/SQL |

### 质量与合规门禁（仅 CLI）

|------|------|--------|

## 三、已知问题与限制

1. ⚠ **`filter` 与 `flatten: true` 同时配置时字段级质量检查被跳过**（pattern/枚举/范围等失效，仅剩数据集级检查）。已在参考模板中规避标注，修复列入 Backlog。
2. ⚠ **`valueParsers` 一旦配置即强制 excel-json 解析**：普通 JSON 配置会报"字典键 '1' 缺失"；CLI 与 API 行为还不一致（API 侧静默忽略 valueParsers）。
3. `maxValues` 参数仅影响控制台报告展示数量，**不会截断** API/Web 返回结果 JSON 中的 `valueCounts`——参数名易误解，使用时注意。
4. API 相对 CLI 的能力差（按需补充）：违规/质量报告导出、Schema 代码导出、PII 报告与门禁、四个质量门禁退出码、审计日志、P6 检查点/续跑/基线、数据库直连、深度分析开关（并行会话开发中）。
5. 深度分析开关在 CLI 与 Web 的命名差异（CLI 部分开关以下划线/连字符风格命名）——以 README 选项表为准。
