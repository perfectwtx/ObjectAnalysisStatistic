# 参数说明

> 本文档以当前 `main` 实际实现为准，说明规则文件、CLI、API、Web 以及平台化任务之间的参数职责。

## 1. 参数分层

ObjectAnalyzer 将配置分为三层：

```text
规则（AnalysisRules）
  ↓ 定义数据质量标准
运行选项（AnalysisOptions）
  ↓ 定义本次如何执行
平台任务（AnalysisJob）
  ↓ 定义如何持久化、追踪和通知
```

规则描述“什么数据是合格的”，运行选项描述“这次怎么分析”，平台任务描述“这次分析如何被管理”。

## 2. 输入参数

| 功能 | CLI | API | Web |
|---|---|---|---|
| 文件输入 | `--input` / `-i` | multipart `file` | 文件上传 |
| 原始文本 | — | `/api/analyze/raw` | — |
| 输入格式 | 自动探测 / 显式 format | `format` | 格式选择 |
| 数据库 | `--connection` + `--query` + `--provider` | — | — |

支持 JSON、JSONL、CSV、Excel、Excel-JSON、XML、YAML，以及 gzip / bzip2 / zip 压缩输入。

## 3. 解析与投影

| 参数 | 说明 |
|---|---|
| `--no-flatten` | 关闭嵌套字段展平 |
| `--root-path` | 从整体 JSON 指定根节点投影，例如 `$.data[*]` |
| `--record-path` | 对每条记录进行 JSONPath 投影，例如 `$.payload` |
| `--no-csv-number-inference` | 关闭 CSV 数字推断 |

## 4. 字段选择与过滤

| 参数 | 说明 |
|---|---|
| `--fields` | 只分析指定字段 |
| `--where` | 使用过滤表达式限制参与分析的数据 |
| `--rules` / `-r` | 加载字段质量规则和运行配置 |
| `--allow-unknown-rules` | 允许规则文件出现未知键 |

## 5. 采样与大数据

| 参数 | 说明 |
|---|---|
| `--sample-reservoir` | 蓄水池随机采样 |
| `--sample-step` | 等距采样 |
| `--checkpoint` | 保存分析检查点 |
| `--resume` | 从检查点继续分析 |
| `--baseline` | 与历史 AnalysisResult 合并 |
| `--max-memory` | 设置内存预算 |
| `--max-memory-mode` | soft / hard 内存超限策略 |
| `--parallel` | 并行度 |
| `--no-progress` | 关闭 CLI 进度显示 |

## 6. 字段质量规则

字段规则位于 `fields` 节点：

| 规则 | 作用 |
|---|---|
| `primaryType` | 期望主导类型 |
| `required` | 必填 |
| `unique` | 唯一性 |
| `enumValues` | 合法值集合 |
| `pattern` | Pattern 校验 |
| `minValue` / `maxValue` | 数值范围 |
| `nullRateMax` | Null 比例上限 |
| `maxOutlierRatio` | 异常值比例上限 |
| `defaultValue` | 缺失字段默认值 |
| `pii` | 自定义敏感字段声明 |
| `redact` | 出站脱敏白名单 |
| `transform` | 值转换 |

## 7. 质量门禁

| 门禁 | CLI | 退出码 |
|---|---|---:|
| 数据质量 | `--fail-on-violations` | 3 |
| PII 合规 | `--fail-on-pii-level` | 4 |
| 异常值 | `--fail-on-outlier-ratio` | 5 |
| Schema 演进 | `--allow-breaking-schema-changes` + `--diff-schema` | 6 |

## 8. 深度分析

当前 Core 支持：

- Pearson / Spearman 字段相关性
- 字符串模式归纳
- Unicode 卫生
- 模糊去重
- 时间序列
- 采样置信区间
- 分布漂移
- Schema 演进

深度分析结果会进入 `AnalysisResult`，复杂结果可随平台 Job 保存到 `ResultJson`。

## 9. 输出

`-o` 根据扩展名自动选择报告导出器：`.json`、`.html`、`.md`、`.csv`、`.xlsx`、`.pdf`。

Schema 能力包括代码生成和 Snapshot / Diff。

## 10. PII 与审计

默认启用 PII 识别与出站打码。CLI 可通过 `--pii-off` 显式关闭。

API / Web 使用统一 `PiiPolicy` 和出站边界负责打码，避免不同入口产生不同安全口径。

审计参数：

- `--audit-log`
- `--operator`

审计记录分析生命周期、输入摘要和运行参数，不记录字段值及密钥。

## 11. 平台化

平台化服务复用 `AnalysisOptions` 和 `AnalysisRules`，不建立第二套分析参数体系。

### AnalysisJob

一次分析任务记录：sourceName、sourceType、status、startedAtUtc、completedAtUtc、durationMs、totalObjects、fieldCount、qualityScore、issueCount、errorMessage、resultJson。

### Quality Snapshot

标准化保存 completeness、validity、uniqueness、consistency、anomalyControl、overallScore。

### AlertRule

支持质量分、完整性、质量回退、严重问题、Schema 破坏性变化和分布漂移等条件。

### Webhook

告警进入 Outbox 后异步发送。失败按照重试次数和退避策略重新投递，最终失败持久化。

## 12. 规则参考

完整规则示例以 `samples/rules_full_reference.jsonc` 为准。

API 交互文档默认位于 `/scalar`，OpenAPI 位于 `/openapi/v1.json`。

## 13. 扩展原则

1. 分析参数优先进入 `AnalysisOptions` 对应功能分组。
2. 数据质量标准进入 `AnalysisRules`。
3. CLI / API / Web 尽可能复用同一配置模型。
4. 平台任务状态、历史和告警不混入分析选项。
5. 新参数必须同步测试、规则参考模板和本文档。
