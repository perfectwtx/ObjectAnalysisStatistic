# Core 计算状态、分析结果与持久化快照

第二阶段将三种职责分开：

| 模型 | 职责 | 能否用于续算 |
|---|---|---|
| `AnalysisAccumulator` / 内部 `FieldAccumulator`、`InternalFieldMetrics` | 观察数据、累计与合并计算状态 | 可以 |
| `AnalysisResult` / `FieldStatistic` | 报告、展示、门禁与导出所需的结果投影 | 不可以 |
| `AnalysisStateSnapshot` / `AnalyzerSnapshot` | 持久化算法状态、配置及可选源位置 | 恢复成计算状态后可以 |

## 使用方式

```csharp
var first = new AnalysisAccumulator(maxTrackedValues: 1000);
first.ObserveRange(firstBatch);

var second = new AnalysisAccumulator(maxTrackedValues: 1000);
second.ObserveRange(secondBatch);

first.Merge(second);
AnalysisResult report = first.Complete();

new AnalyzerSnapshot
{
    PositionKind = "batch",
    State = first.Capture()
}.SaveTo("combined.snapshot");

var restored = AnalyzerSnapshot.LoadFrom("combined.snapshot").State.Restore();
restored.ObserveRange(thirdBatch);
AnalysisResult updated = restored.Complete();
```

`Observe()` 接受以 `FieldPath`、`RecordValue` 表达的类型化记录；`ObserveRange()` 兼容现有字典记录，并支持线程并行处理。原有 `ObjectAnalyzer.Analyze()` 和 `AnalyzeDetailed()` 使用同一套计算状态实现。

计算状态采用单一所有者模型：不要同时对同一实例调用观察、外部合并、完成或捕获。一次 `ObserveRange()` 内部可以并行。遇到异常或取消后应丢弃该次未完成的状态，不能假定它是事务性更新。

`Complete()` 不消耗状态，也不会将最终报告的均值、分位数等结果反写成计算依据。报告与捕获的快照均断开必要的可变集合共享；修改报告不会修改计算状态。结果 DTO 暂时保留 setter，供现有宿主追加报告信息，但已经移除 `MergeFrom()`，不再承担续算。

## 保存了什么

- 字段出现次数、null 次数、类型频次及数字表示能力。
- 有界的类型化值频次与未保留的出现次数。
- 有效数值样本数、数值总和、Welford 均值与 M2。
- 有效字符串样本数、长度总和、长度极值和语义计数。
- 日期计数、极值和原始分钟桶；展示用日期桶在收尾时重建。
- 分位数草图的容量与质心、HLL 的精度和非零寄存器。
- 所有对象的 128 位哈希及出现次数，用于识别跨批次重复对象。
- 有界的对象 JSON 样本，以及管线补充的关系、转换失败计数和过滤表达式。
- 规则与功能配置。调用方修改最初传入的配置，不会改变已建立的状态。

数值与字符串样本数使用 long。均值和标准差按各自的有效样本数计算；例如数字、字符串和 null 混合的字段，不会用字段总出现次数加权数值均值。

对象去重仍采用哈希身份，保留哈希碰撞的理论可能性。哈希计数所需内存与不同对象数量有关；JSON 样本有界，报告最多输出 10000 个重复组样本。样本不足不会降低重复组总数和不同对象总数的统计范围。

## 合并语义

全量、并行分块和增量分析使用相同的字段计数和指标合并实现。合并不会修改源状态，禁止将一个状态合并到自身。

规则、功能选项和频次容量必须一致；有数据的管线状态还需使用一致的过滤表达式。宿主保存的执行签名进一步检查展平、字段选择、投影和采样配置等。不同配置的状态明确拒绝合并。

频次截断改为保留规范身份排序最小的 N 个值，不再取决于线程先后或首次出现顺序。被保留值的计数与溢出次数满足计数守恒；HLL 观察完整值域，不依赖保留样本。频次表不是按出现次数选出的 Top-N。

分位数和 HLL 仍为近似算法；浮点累计也可能受运算顺序影响。分块后比较时应使用适合算法的误差标准，不能要求所有浮点值逐位一致。

当前持久化与外部合并支持基础统计和基于日期状态重建的时间序列。相关性蓄水池、字符串模式、Unicode 卫生和模糊去重暂时没有本阶段的持久化协议，启用时会拒绝捕获或外部合并。普通完整分析继续支持这些功能；后续分析器组件化再扩展其协议。

## 检查点 v3

外层格式为 `object-analyzer.snapshot/v3`，内部状态格式为 `analysis-state/v1`。文件保存 `state`，不再保存最终 `result`。`AnalyzerSnapshot.Result` 仅保留只读的兼容投影，不参与序列化和恢复。

读取时先检查版本，再验证计数、草图和对象计数的一致性。v1/v2 检查点及普通报告缺少可靠续算信息，一律要求重新分析。

写入使用同目录的唯一临时文件，序列化成功后再替换目标文件；失败时清理临时文件，避免先删除旧检查点。当前检查点在分析成功结束后写入，不提供运行中定期落盘。

检查点包含恢复所需的原始值样本和规则数据，属于计算状态文件，不是用于分发的脱敏报告。

## CLI 与 Web

### CLI 同源续跑

`--checkpoint` / `--resume` 当前要求未压缩的 JSONL 输入。源游标使用物理行号，包含空行和过滤后未参与统计的记录；与 `TotalObjects` 分开保存。

续跑校验源路径、已处理行前缀的 SHA-256 和执行配置，允许追加数据，拒绝修改已处理内容。源文件在读取和检查点保存期间应保持稳定。

采样、内存自动回退、根投影及上述未支持持久化的高级功能不能与位置检查点组合。其他输入格式需先建立可靠的源游标协议，不能借用分析结果条数推断位置。

### 独立批次累计

`--baseline` 现在接受 v3 状态快照，将历史状态与本批输入合并，不跳过本批数据。普通 `--output` JSON 报告不再作为累计基线。

Web 上传的状态按独立批次导入，保存时使用 `positionKind: "batch"`，不声称能够定位下一次上传文件的位置。合并后的新报告在作业持久化之前交给宿主，原报告不再就地做数学合并。采用采样或内存回退的管线不提供可供该出口续算的状态。

Schema Diff 和分布漂移仍使用各自的比较快照。它们用于比较历史结果，不能代替这里的计算状态。

## 验证范围

回归覆盖有效样本数、单样本方差、跨批次重复对象、不同分块顺序、有界频次、HLL、分位数与日期状态往返、报告与快照独立性，以及追加数据、空行、过滤、源变更、配置变更、旧版本拒绝和失败写入。
